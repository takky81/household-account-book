# 開発環境

## 用意するもの

- Node.js（バージョンは `.nvmrc`。現在 22.22.3）
- Docker（ローカル Supabase が使う）

## 立ち上げ

```bash
npm install
npm run db:start
```

`db:start` は Docker で PostgreSQL・PostgREST・Auth などを立ち上げ、`supabase/migrations/*.sql`
を順に流す。ポートは blank-study と重ならないようにずらしてある。

| 用途 | ポート |
| --- | --- |
| API（PostgREST / Auth） | 54421 |
| PostgreSQL | 54422 |
| Studio | 54423 |
| Mailpit | 54424 |

環境変数を用意する。

```bash
cp .env.example .env.local
npm run db:status   # ANON_KEY を .env.local の VITE_SUPABASE_ANON_KEY に書き写す
npm run dev
```

## アカウントを作る

サインアップは閉じてあるので（`supabase/config.toml` の `enable_signup = false`）、
利用者は Studio（http://127.0.0.1:54423）の Authentication から作る。作ると
`auth.users` のトリガが `profiles` の行を作る（表示名はメールアドレスのローカル部。
重なれば `-2`、`-3` と連番）。

未分類カテゴリは全ユーザー共通で収支区分ごとに1件なので、利用者ごとには作られない。

## テスト

```bash
npm test          # ユニット（Vitest）
npm run db:test   # DB（pgTAP。supabase/tests/*.test.sql）
npm run test:e2e  # E2E（Playwright。先に db:start と dev が要る）
```

`db:test` は各ファイルをトランザクションで走らせて最後に巻き戻すため、開発中のデータは消えない。
RLS と RPC の検査はここでやる。`auth.users` に直接 INSERT して利用者を作り、
`set local request.jwt.claims` と `set local role authenticated` でその人になりすます。

## マイグレーション

```bash
npm run db:migration <名前>   # supabase/migrations に空のファイルを作る
npm run db:reset              # 全部流し直す
```

流す順に意味がある。テーブル → 判定関数とトリガ → RLS と GRANT → RPC → 関数の EXECUTE、
の順で、後ろのファイルが前のファイルの定義に依存している。

## 決定表

```bash
npm run spec            # spec/dist/index.html を作る（コミットしない）
npm run spec:coverage   # 各列がテストで押さえられているかを数える
```

カバレッジは「対応するテストファイルの中に `列N` と書いてあるか」で見る粗い確認。
DB のテスト（`.sql`）は1ファイルで複数の表を扱うため、表の名前と列番号が同じ行に
並んでいることを求める。
